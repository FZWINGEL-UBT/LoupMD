# AGENTS.md — LoupMD Engineering & Workflow Guide

Practical rules, commands, invariants, and hard-won lessons for working on LoupMD (`round6-hardening`).

## 1. Repository Layout & Two Execution Paths

- **Specialised path (`MACE-OMAT-0 medium` only):**
  - `src/engine.cu`, `src/interaction0.cu`, `src/generated_kernels.cuh`, `src/generated_kernels_signature.h`.
  - Generated by `python/gen_kernels.py` (from FastMACE schedules + factored symmetric contractions).
- **Generic path (all other families + `--generic` / `LOUP_GENERIC=1`):**
  - Covers `MACE-OMAT-0 small`, `MACE-OFF23-S/M/L`, `MACE-OFF23b-M`, `MACE-OFF24-M`, `MACE-MH-1`, `MACE-POLAR-1-S/M/L`.
  - `src/generic.cu`, `src/generated_generic.cu`, `src/generated_generic.cuh`, `src/generic.hpp`.
  - Generated by `python/gen_generic.py`.
  - `src/polar.cu`: long-range k-space electrostatics + local-environment MLP for `MACE-POLAR-1`.
- **Shared infrastructure:**
  - `src/neighbors.cu` (cell-list / CSR edge build, `scatter_active_edges_kernel` for `PRELOC`), `src/integrator.cu`, `src/sgemm.cu` (custom SIMT `sgemm128` + cuBLAS/cuBLASLt autotune & plan cache), `src/model_loader.cu`, `src/bundle.cu`, `include/loupmd.h`.
- **Do not touch `.internal/`** unless explicitly asked.
- **Keep `OPTIMISATION_LEDGER.md` and `STATUS_AND_PROFILE.md` current:** every attempted optimisation (adopted or rejected) gets an index row + appendix entry; never delete rejected entries. Note `5060 Ti only` whenever `sm_89` workstations were not tested.

## 2. Build, Environments & Shell Rules (WSL)

- **Always build and run in WSL (`wsl bash`).** Local GPU is **RTX 5060 Ti (`sm_120`)**. Do not touch remote workstations unless explicitly instructed.
- **Build command:**
  ```bash
  make -j4 CUDA_ARCH=sm_120        # builds build/sm_120/libloupmd.so and copies to ./libloupmd.so
  make -j4 CUDA_ARCH=sm_120 build/sm_120/libloupmd.so  # side build without overwriting ./libloupmd.so
  ```
  - **Never overwrite `./libloupmd.so` while another process has it loaded.** Build to `build/sm_120/libloupmd.so` and copy to a side name (e.g. `libloupmd_cand.so`), then test via `LOUP_LIB=/abs/path/to/libloupmd_cand.so`.
  - **Never mix object files across `CUDA_ARCH`:** `OBJDIR = build/$(CUDA_ARCH)` prevents silent linking of mismatched arch `.o` files (which links cleanly and fails at runtime with `invalid device function`).
  - Per-TU `-MMD -MP` deps live in `build/sm_120/*.d`; single-`.cu` incremental rebuilds take ~2–3 s.
- **Python environments:**
  - **Runtime, benchmarks, gates, `pytest`, `gen_generic.py`:**
    `/home/fzwin/environments/mace_cueq_latest/bin/python` with `TORCH_FORCE_NO_WEIGHTS_ONLY_LOAD=1`.
  - **`gen_kernels.py` (needs `openequivariance`):**
    `/home/fzwin/environments/mace_cueq_oeq/bin/python` with `CUDA_VISIBLE_DEVICES='' TORCH_FORCE_NO_WEIGHTS_ONLY_LOAD=1`.
  - Models live in `/home/fzwin/models/`.
- **`gen_generic.py` caching:** caches per-model IR in `~/.cache/loupmd/gen_generic_cache.json` (`< 1 s` warm vs `~85 s` cold; `--no-cache` forces rebuild; `--warm` updates cache only). Auto-discovers models in `/home/fzwin/models` and skips unsupported shapes (e.g. `> 1024` channels).
- **WSL / bash gotchas:**
  - Outer shell redirects (`> /tmp/...`) write to Windows `/tmp`, not WSL `/tmp`. Keep scratch scripts in `.tmp_o/` and delete them before finishing.
  - Always run `sed -i 's/\r$//'` on `.sh` scripts written from Windows before executing in WSL.
  - Write `.sh` script files instead of passing `$var` / `awk` inside nested `wsl bash -c "..."`.
  - Always use `set -euo pipefail` (and `&&`) when generating + building: a failed generator script can otherwise leave a stale `.cuh`/`.cu` on disk that `make` silently compiles.

## 3. Correctness, Precision & Gate Rules

- **Accuracy gate (`python/test_gate.py`, 3× float32-vs-float64 rule):**
  - `dE <= max(3 dE32, 0.01 meV/atom)`
  - `dF <= max(3 dF32, 1e-5 eV/A)`
  - `dS <= max(3 dS32, 1e-7 eV/A^3)`
  - Reference cache lives in `~/.cache/loupmd/gate_refs/` (`--no-ref-cache` recomputes).
  - **Large models (`OFF23-L`, `OFF23b-M`, `OFF24-M`, `POLAR-1-L`)** exceed 16 GB VRAM alongside two PyTorch models: pass `--ref-device cpu`. Note: computing an uncached `MACE-POLAR-1-L` CPU float64 stress ref on `NbCl5` takes many minutes; for fast smoke checks during iteration compare candidate vs a gate-verified baseline `.so`, then run `test_gate.py` before adoption.
  - `POLAR-1-S NaNbO3_c0` is marked `UNSTABLE` (skipped unless `--include-unstable`) because MACE float32-vs-float64 itself diverges there.
- **Precision constraints (non-negotiable):**
  - **NO FP16 / BF16 / FP8 / `1xTF32`** on the force path (and no BF16x9 emulation).
  - **Long-range `MACE-POLAR-1` models MUST use float32 SIMT GEMMs only** (`3xTF32` hybrid cubins failed `POLAR-1-S/-L` stress gates and produced NaN on `NaNbO3_c0`).
- **Packed-table error guard (`loup::PackErrTracker`):**
  - Both loaders enforce `kPackedTableMaxRelErr = 5e-4` across physical intervals (`r >= 1 A`). Check with `LOUP_DEBUG_PACK=1`.
- **Variant / path test overrides (`src/engine.cu`):**
  - `LOUP_SPLINE_VARIANT=R1|R1p|R4|R4p|R5`, `LOUP_WPRIME_THREADS=256|512`, `LOUP_WPRIME_RCV=0|1`, `LOUP_REORDER=0|1`, `LOUP_GENERIC=1`, `LOUP_NO_PRELOC=1`, `LOUP_LIB=/path/to/lib.so`; `LOUP_POLAR_FOLD=0` (`src/polar.cu`: the unfolded SCF / electron-energy GEMMs that non-`sm_120` GPUs run).
  - When editing the POLAR SCF or electron-energy GEMMs, gate both paths (default and `LOUP_POLAR_FOLD=0`).
  - When editing `spline_forward_inter1` or `wprime_backward_inter1`, gate every forced variant (`R1`, `R1p`, `R4`, `R4p`, `R5`), not just the auto-selected one.
- **Test suite:** run `pytest -q` (full suite, including `tests/test_engine_guards.py` and `tests/test_gate_cache.py`) against the installed `./libloupmd.so` before finishing.
- **Bundle / signature compatibility:** `LOUP_KERNEL_SIGNATURE` in `src/generated_kernels_signature.h` must match `export_omat0.kernel_signature()`.

## 4. Benchmarking & Profiling Discipline

- **4-stage fast funnel (~70–75 s) before full ABBA:**
  1. Incremental build to side `.so` (`build/sm_120/libloupmd.so` -> `libloupmd_cand.so`).
  2. Single-eval force/stress/energy delta vs baseline `.so` (`cmp_libs`).
  3. 10-eval `nsys` kernel profile (`--cuda-graph-trace=node`) on the target kernel regex.
  4. Quick 2×128 Langevin ABBA with pinned plans (`LOUP_CACHE_DIR=/tmp/plans_dev`).
  If the target kernel doesn't improve or quick ABBA `b/a >= 1.0`, reject immediately without burning 5–10 min on full multi-family ABBAs.
- **Adoption bar (`OPTIMISATION_LEDGER.md`):**
  - An optimisation is adopted only when it passes the 3× accuracy gate AND wins or ties in **both build orders (`A B B A`) on both GPUs (`sm_120` and `sm_89`)** — unless the owner explicitly narrows hardware scope (in which case record `5060 Ti only` in the ledger and status file).
- **Full A/B (`ABBA`):**
  - Run `A B B A` in separate subprocesses (`median` of 6×256 Langevin steps, 300 K, 1 fs, skin 0.5 Å, friction 0.01/fs after 100 warmup steps) and check `final_temperature_k` (~290–315 K).
  - Small `POLAR` cells (`nacl216`) exhibit ±2–3% plan-choice spread across fresh autotune runs. Use a fresh `LOUP_CACHE_DIR=/tmp/fresh_plans` for POLAR ABBAs, and **never mutate `~/.cache/loupmd/` plan files without telling the user**.
  - `cublasLt` GEMMs must be timed **inside CUDA graph replay**, not eager calls.
  - `cublas_bind` (`cublasSetStream` + per-lane workspace) must run on every forked stream (`fork()` / `lane(k)` / `join()`).

## 5. CUDA Kernel Lessons Learned (Don't Repeat Dead Ends)

- **Inspect SASS & resource usage offline first (~1 s):**
  ```bash
  cuobjdump --dump-resource-usage build/sm_120/<unit>.o
  cuobjdump -sass build/sm_120/<unit>.o
  ```
  Watch for `STACK > 0` register spills, register occupancy cliffs (e.g. `spline_forward_inter1<5, false>` needs `<= 96` regs and `<= 16 KB` smem to fit the 16 KB L1 carveout), and `SHARED > 48 KB` (`cudaFuncAttributeMaxDynamicSharedMemorySize`).
- **Verify DRAM-bandwidth vs issue/latency bound before optimising:**
  - Bandwidth-saturated kernels (`inv`, `bcast_mul`, `sc0_backward`, `assemble_forces`) gain nothing (`b/a ~ 1.000`) from removing integer divisions, fixing small spills, or hoisting scalar math.
  - Conversely, issue-bound / L1-L2-thrashing kernels give real wins:
    - **`sf_kernel_tiled` (`src/polar.cu`, 5060 Ti only so far):** tiling `8` `k`-vectors (`8` warps) per block around one SoA shared-memory tile `s_X[NC][129]` + `s_frac[3][129]` eliminated `K×` L1/L2 thrashing on `X` (`-7.4%`, `27.00 -> 25.00 ms` on `POLAR-1-M nbcl5`). Keeping `__launch_bounds__(TK * 32)` without a `minBlocks` cap avoids `STACK:40` spills on `NC = 16`.
    - **`sgemm64` (`src/sgemm.cu`, `sm_120` `M <= 1600`):** `64 x 64 x 16` `cp.async` SIMT GEMM (`128` threads) scoped to `sm_120` and `M <= 1600` cuts small-cell GEMM starvation (`POLAR-1-S/M/L NaCl216` `-12%` to `-16%`, `MH-1 NaCl216` `-8.1%`, `OFF23-M water216` `-6.2%`). Do **not** enable `sgemm64` unscoped on `M >= 1944`: it wins hot-L2 autotuning (`< 16 MB` `A`) then re-reads cold `A` twice as often in the step.
    - **Staged CG linear forms + cubic bias-folded decode (`gen_kernels.py` / `gen_generic.py`, 5060 Ti only so far):** computing per-edge `CONST * she[m]` linear forms once in `s_sh` instead of per channel thread cuts `gconv_fwd_L1`/`L2b` (`OFF23-M` `-6.8%`, `OFF23-L` `-4.4%`, `OMAT-S` `4.82 -> 4.77 ms`); pairing it with `w'` cubic decode + `TILE = 16` in `spline_forward_inter1` cuts `OMAT-0` medium `SrTiO3` `8.40 -> 8.28 ms`.
- **Avoid stripping `__restrict__`:** keep `__restrict__` kernel pointer parameters directly typed rather than aliasing them through local pointer arrays (`const float* ptrs[3]`).
- **Watch occupancy, L1 carveout & thread parallelism:**
  - Don't set `PreferredSharedMemoryCarveout = 0` blindly on `sm_120`: the driver drops shared config to `8 KB` (`gconv_fwd_L1`) or `32 KB` (`gconv_bwd_L1`), capping each SM to 1 block (`-40%` slowdown).
  - Don't serialize `m = 0..2l` inside 2D elementwise kernels (`bcast_mul` lost when serialized).
  - Don't force receiver-level serial tails (`first_bwd` edge-tail fusion regressed `990 -> 2,243 us` because 2 lanes/warp serialized sender/ZBL work; keep ZBL + force/virial assembly in `assemble_forces_kernel` with `float32` ZBL arithmetic, `zbl_r_max_max` early exit, and warp-level reductions).
- **Check `STATUS_AND_PROFILE.md` & `OPTIMISATION_LEDGER.md` before proposing:**
  - `LOUP_REORDER=1` (Morton/Hilbert) hurts on `OMAT-0`, `OFF23`, and `MH-1`.
  - Slab-run sharing beyond pairs saves only ~5% at 300 K (not 5–10×).
  - `PRELOC` (`act_slab`, `act_t_sx`) only matches layers sharing `preloc_grid()` and `pair_sym == 1` (`POLAR-1` / `MH-1` L2 may differ from L0/L1).
