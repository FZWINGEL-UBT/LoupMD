# Loup-S training engine: design before Stage 1

**Decision:** keep every Stage 0 run on `mace-torch==0.3.16`. For Stage 1, design an in-house **differentiable backend**, not a second MD engine or a new optimizer. Start at the energy model boundary. Keep the mace-torch training loop, loss and checkpoint reader as long as they serve that boundary. A new loop is justified only if a profile implicates the loop itself or a required loss cannot be integrated into it. Stage 1 can start on mace-torch if the candidate fails qualification.

**Status:** proposal, not an implemented or benchmarked backend. No change to active training, compute permissions, Stage 0 datasets, checkpoints, or the engine’s release gate. The [parent design](../LOUP_S_DESIGN.md) defines architecture, fidelity and stage exits in §§4, 5, 7 and 10; the [Stage 0 plan](loup-s-stage0.md) owns run history and spend.

## What is being replaced

| Boundary | Reference and candidate contract |
| --- | --- |
| Input | Existing `train.py` validates frozen split digests, head/species, trajectory separation and labels. Same frame order, graph membership, weights, precision policy, element map and normalization on both backends. |
| Model | A trainable energy function returns per-graph energies and, where defined by the architecture, per-atom readouts. The orchestration requests forces and tensile-positive stress by differentiation. No independently fitted force head. |
| First implementation | Stock `s64r8` is the initial derivative/optimizer reference, not a fidelity-qualified student. Keep the failing `s64l0` checkpoint for reproducible debugging; do not use it to qualify a recipe or claim time to target. Implement an unfused Torch reference for `C_msg < C` where stock MACE has no equivalent. Replace one measured hot operator at a time. |
| Optimization | Upstream owns loss normalization, parameter groups, optimizer, EMA and schedule initially. Hold them fixed for a backend comparison. Preserve a runnable unfused reference, not just a set of golden predictions. |
| Output | For stock shapes, produce the physical-energy `student.model`, the specified pre-phase-two checkpoint and existing manifest. `publish.py` gates the exact bundle against the student. A Stage 1a experimental shape without an exporter is a Torch training result, **not** a released engine model. |

Do not adopt a generic foundation-model trainer, distributed optimizer, new graph compiler, or new bundle format as a prerequisite. First support periodic, single-head, two-layer scalar-sender students. The wider parameter study (water, more species, narrowed messages, cutoffs, vector senders) can use the Torch reference when an optimized implementation has no matching signature. Never silently change the model to make a fast path applicable.

## Math and operator boundary

Use a separate infinitesimal strain for each graph. With row-vector Cartesian positions, reference edge index `(s,t)` = (sender,receiver) and integer image `n`, mace-torch uses **`d = r_t − r_s + n H`**. Both positions and periodic images strain: `d' = d (I + sym ε)`. Keep directed edges and distinct images, including `s=t, n≠0`; exclude the zero-image self edge. Set `F = −∂E/∂r` and `σ = (∂E/∂ε)/|det H|` at zero strain. Full tensors, ASE tensile sign, potential stress only; virial is `−Vσ`. Do not use a minimum image or assume invariance of odd harmonics under edge reversal. Source: pinned `mace.modules.utils.{get_symmetric_displacement,get_edge_vectors_and_lengths,compute_forces_virials}`.

For a scalar batch loss let `a = ∂L/∂E`, `b = ∂L/∂F`, `C = ∂L/∂σ`. With independent frames and fixed labels/geometry, its parameter gradient is the parameter derivative of the contracted scalar

```
sum_g a_g E_g + D_(r, ε) E_batch [−b, sym(C_g)/V_g],  evaluated at ε = 0.
```

Here `E_batch` is the sum of graph energies for the directional derivative. Treat the three incoming loss sensitivities as constants **in this formula only**; do not accidentally differentiate them twice. Energy normalization, stress weights, masks and reduction factors enter these sensitivities. This is a mixed derivative, not a full coordinate Hessian and not a finite-difference training algorithm.

**First exact implementation:** ordinary Torch energy, first `autograd.grad` for forces/strain with `create_graph=True`, then backpropagate the actual loss into parameters. A fast op must also differentiate its backward: gradients with respect to saved operator inputs **and the upstream gradient** are needed. Do not wrap an inference `.so` call in a forward-only custom op. The contracted form above provides an independent oracle and a possible native algorithm if retained activations dominate; do not maintain two native derivative engines before the first one pays off.

**Stock algebra to preserve.** The recipe says `MACE`, but the pinned builder constructs `ScaleShiftMACE`. Its `forward` adds ZBL and the learned per-atom readouts **before** applying the model's interaction scale and shift; frozen species E0 is added separately. Differentiate the interaction energy for F/stress, not a rounded total with a large constant offset. `ZBLBasis.forward` half-counts each directed pair and applies its own core cutoff; its fixed parameters do not make its force or stress zero. Test a core-active pair. Preserve component-normalized harmonics, eight Bessels with the polynomial cutoff before the MLP, per-layer `avg_num_neighbors` division, e3nn path factors, skips, and every occurrence of each feature in the symmetric product. Fixed coupling coefficients are reusable; species-specific product weights must stay live.

**Centered FP32 also qualifies the repulsive core.** Compare pinned `ZBLBasis.forward` in FP32 vs FP64 at the shortest observed distances by species pair, on core-active pairs, and just inside/outside the pair-specific covalent cutoff. Check finite pair energies, radial derivatives, total forces and all stress components, after applying the interaction scale; use absolute floors near zero. Test strictly positive separations, not a singular overlap. A negative exponential need not overflow for a positive radius; division by a small radius and cancellation in the cutoff or its derivative still matter. Keep this term in FP64 if it fails, and qualify that **hybrid**, not the failed FP32 path. Precomputation is valid only on immutable frames with fixed ZBL parameters and a correctly applied interaction scale.

**Example candidate, not a measured hotspot:** for one channel/degree in layer 1, `p_i = Σ_edges wθ(d) Y(d) x_j`, `x_j = h_j U`. Its directional derivative sums `(ẇ Y + w Ẏ) x_j + w Y ẋ_j`, where `ẋ_j = ḣ_j U` for a geometry-only direction. Differentiating that contraction with respect to weights must reach the radial MLP, `U`, and the preceding representation that produced both `h` and `ḣ`. Directed reductions must scatter contributions to all repeated senders/receivers. A native op may start **below** the radial MLP, taking `w`, `Y`, `x` and integer edge indices, so the ordinary Torch chain rule still reaches trainable radial weights. Select the boundary from the profile. Preserve the actual path factors, channel ordering and cutoff envelope from the reference; the scalar expression is not an alternative normalization.

Proposed interface: `aggregate(x[N,K], w[E,K,L+1], Y[E,(L+1)²], sender[E], receiver[E], N) → A[N,K,(L+1)²]`, where `E` here is directed edge count. For an incoming adjoint `G`, gather `G[receiver]` per edge. Accumulate `Σ_lm G w Y` at the sender for `∂L/∂x`; sum `G x Y` over `m` for `∂L/∂w_l`, and `G x w` over channels for `∂L/∂Y`. The derivative of this backward must propagate through `G` itself. Register any CUDA replacement through `torch.library` with shape/meta and autograd rules, the current Torch stream, no mutation of saved tensors, no hidden parameter state. Start with a differentiable ATen backward; require `opcheck` for registration plus numerical `gradcheck` and `gradgradcheck` with arbitrary cotangents. Cover empty edges and nonempty periodic self-images: a one-atom cell can have zero net force and nonzero stress.

`A[N,K,(L+1)²]` denotes **logical axes**, not a mandated memory layout. e3nn orders multiplicities within irrep blocks; do not reinterpret its flattened buffer as either dense axis order without mapping the blocks. Compare `[N,(L+1)²,K]` with contiguous channels (`ir_mul`) and the reference layout, including pack/transpose and saved-adjoint traffic across both neighbors of the operation. At `K=64` a warp can access consecutive channels; that does not establish an epoch win. Both baseline interactions have scalar senders but use harmonics through `l=3`: the message needs path factors and directed angular products, not general input-irrep CG sums. The **product block** couples those angular channels. Profile `SymmetricContraction` independently of `aggregate`, including parameter backward. Vendored [`sc_factored.py`](../loupmd/export/_vendor/fastmace/kernels/cuda/sc_factored.py) and [`sc_generated.py`](../loupmd/export/_vendor/fastmace/kernels/cuda/sc_generated.py) are schedule references, not trainable kernels. If the trace implicates edge weights, compare the materialized reference with streaming the last radial projection into the reduction. Charge recomputation, parameter gradients and outer-backward workspace; do not infer bandwidth saturation from tensor shape.

In parity mode, keep MACE's original optimizer parameterization. Combining two dense maps into `U` **on the tape** is not the same as optimizing their product as one parameter with Adam. A deliberately reparameterized Stage 1 model needs its own eager oracle. The inference exporter is not that oracle: `loupmd/export/generic.py` (`RadialChain`, `refine_for_packing`, `product_tensors`) samples/packs radial functions and folds current weights. Reuse algebra and data-layout ideas, not those detached tables or folded float32 weights as training state.

Keep topology and parameters separate. Cache atom/species maps, image integers, edge indices, graph pointers, and optional deterministic edge permutations for immutable frames. Key by geometry/cell/PBC, element mapping, cutoff and edge convention. Rebuild for a changed cutoff, deformed/displaced geometry, relabelling round with new frames, or changed convention. In the first implementation compute differentiable distances, bases and harmonics from positions/cell. Detached cached feature values alone give wrong forces or stress; storing geometry Jacobians is a different memory/performance decision. Never cache learned radial tables, folded trainable maps, activations or derivatives across optimizer steps. Treat the exported inference bundle as an output, not the master copy of training parameters.

Two Torch candidates need **no persistent geometry-feature cache**. (1) Match `(s,t,n)` to `(t,s,−n)` with multiplicity, including nonzero periodic self-images. If pairing is complete and radial inputs are reversal-invariant, evaluate the radial MLP once per pair, gather its output to directed messages, sum both radial adjoints once. Keep the directed harmonic signs and their derivatives. This halves radial MLP *rows*, not measured runtime, total activations or memory; charge the pairing map and gather/reduction. (2) For strictly one-hot elements, look up the correct embedding and use species-indexed skip maps, preserving original parameters, path normalizations and branches. Compare dense-parameter gradients (including absent species under decay/AMSGrad), resulting moments and EMA; no sparse/lazy optimizer substitution. Neither rearrangement promises bitwise equality. See the [pair census and CPU derivative control](loup-s-training-review.md).

## Training loop and artifacts

Keep three interfaces separate: **batch → differentiable energy**, **loss + optimizer step → new training state**, and **selected model → physical artifact**. Initially replace only the first, using Torch modules with the original parameter and buffer names or an explicit, complete mapping. A fast operator must not know about epochs, file paths, averaging or publication. The following are the compatibility requirements if we later own the second interface.

**Batch and statistics.** Use the *materialized* files from [train.py](../loupmd/distill/train.py) (`_inspect_sources`, `write_inputs`, `plan_job`) as oracle, not just the raw extxyz digests: the wrapper rewrites labels, strips loss-weight overrides/constraints, and may center energies. Record both sets of hashes, the ordered species table, units, head, and actual train/validation batch frame IDs. Fit base-train E0 by minimum-norm FP64 least squares even for a fixed, rank-deficient stoichiometry. For FP32 subtract E0 in FP64 before casting, leave F/stress alone, train with zero E0 and restore the offsets **once**, by atomic number, in the physical double-precision artifact. Preserve train-derived force RMS scale, zero interaction shift and actual neighbor normalization. The reference averages incoming counts over receivers that occur in the edge list; zero-degree receivers do not add a sample to that average.

MACE already constructs its fixed graph dataset once **per invocation**, not once per epoch. Separate topology keys from labels (teacher/head, split/file, dtype and E0 transform) and statistics keys (ordered base/harvest set, sampling and batch policy). The reference train loader shuffles and drops partial batches; validation retains them. Statistics can consume the shuffled loader before epoch 0. Pack disjoint graphs with atom offsets, `ptr`, per-edge image and per-graph cell; never batch by edge count in a parity test if that changes optimizer steps. Graph bucketing or microbatching is a separate experiment.

**One reference update.** For `B` graphs, each with `N_g` atoms, unit frame/property weights and `Δ = prediction − reference`, pinned `WeightedEnergyForcesStressLoss` uses:

```
L_E = sum_g (ΔE_g / N_g)^2 / B
L_F = sum_ia ΔF_ia² / (3 * sum_g N_g)
L_S = sum_gab Δσ_gab² / (9 * B)
L   = w_E L_E + w_F L_F + w_S L_S
```

Both shear entries count. Weights are `(1,100,1)` then `(1000,100,10)`. With microbatches, divide by the full effective-batch denominators, then clip/update once. Reference order: zero grads to `None` → differentiate scalar loss → global L2 clip at 10 → Adam with AMSGrad (not AdamW, match group-specific decay) → `torch_ema` update. Reuse the pinned group builder, including parameter order; record actual optimizer flags, LR, EMA update count and decay behavior. Compare `None` vs numerical zero, raw gradients before and after clipping, raw parameter deltas, all moment tensors and EMA after a step with already-populated optimizer state. A cold first step alone misses bugs.

**Phases and selection.** Match the initial evaluation, phase-one plateau scheduler driven by previous EMA validation, phase-two loss and SWALR transition, and separate SWA and EMA states. The .01 → .001 rates are the recipe’s initial and phase-two rates; don't ignore intervening plateau reductions. Pinned `mace.tools.train.MACELoss` accumulates reduced validation-batch loss scalars and divides by total graphs; reproduce that quantity for the scheduler, even when the last validation batch is short. It is not a held-out physical metric. The wrapper publishes the **last stage-two EMA** model, not best validation or the SWA accumulator. Compare exact event order across the 110→111 epoch boundary in the current 150-epoch recipe.

Validation may use larger **physical** disjoint batches on a frozen EMA snapshot if they fit. Restore original atom `ptr`, weights/masks and graph order; compute losses and all metrics on the original **8/8/8/6** logical groups for 30 frames. Never reduce one 30-frame loss and divide by 30. Check loss, plateau LR events and checkpoint selection against the original grouping in both phases, especially near thresholds; larger contractions can change floating-point results. Validation still requires position and strain gradients, but no parameter mixed derivative.

| State transition | Contract |
| --- | --- |
| **New learning-curve point** | New fit and base statistics from its own frozen train set; same held-outs. Never warm-start the learning curve. |
| **Closed-loop branch** (required existing behavior) | Start from a completed parent, unchanged recipe/base splits, additional cumulative harvest and verified `pre_stage_two.pt` from epoch 110. `restart_paths` / `_seed_resume` preserve the original boundary file and create the epoch-111 `_swa` restart with group LR set from `swa_lr`. Keep parent E0 and neighbor normalization. Record ordered child data identities; do not flatten this into “resume latest.” |
| **Crash recovery** (proposed for an owned loop) | First support committed epoch boundaries only: discard and replay an interrupted epoch. Snapshot raw weights/buffers **outside the EMA swap**, parameter-group/optimizer slots, both schedulers, EMA/SWA values and counts, next epoch/pending event, best/previous validation, and all used loader/Python/NumPy/Torch CPU/device RNG states. Persist ordered batches or sampler state that reproduces them. Reject changed data, architecture, schedule, backend or parameter mapping. Test interruptions on both sides of validation/phase switch. Do not promise bitwise results across devices. |
| **Inference artifact** | Restore canonical weight **and buffer** mapping, reload physical FP64 model and compare E/F/stress. Use [publish.py](../loupmd/distill/publish.py) unchanged for supported models. It checks `student_sha256`, runs the gate and only publishes the exact gated element-set bundle. Unsupported ablations are explicitly training-only until Stage 1b. |

Do not confuse the second and third rows: pinned `mace.tools.checkpoint.CheckpointBuilder` writes `model`, `optimizer`, `lr_scheduler` only. The saved model can be EMA-swapped while the moments belong to raw training. It lacks enough state for exact same-run continuation. The real four-epoch smoke manifest identifies boundary epoch 1 and final epoch 3; a downloaded intermediate `.pt` is neither automatically that boundary nor a full recovery state. For native same-run checkpoints, write immutable generations on one filesystem, flush and hash payloads, publish a completion manifest last, retain the previous verified generation and parent boundary; never accept a torn checkpoint by newest filename.

**Stage 1 loss extensions:** molecule net force is the sum of atomic forces, not the average; torque uses positions unwrapped relative to the mass-weighted center. The current `write_inputs` drops molecule arrays: explicitly supply validated ID/mass grouping keyed by frame if using this loss. Tail and per-species weighting change force sensitivities, not the energy model. The curvature ablation uses a **paired force difference** at displaced coordinates, with matched atoms/probes and opposite signed sensitivities; it needs two ordinary force graphs, not third derivatives. Keep these off in reference parity runs.

## Profile before writing a kernel

**Evidence:** the 300-frame FP64 L4 runs measured 48.6 s/epoch (`s64l0`) and 43.5 s/epoch (`s64r8`) over 20 successive phase-one intervals, including the current validation/save cadence. At 1.94 CU/h this is 0.0262 and 0.0234 CU/epoch, **not cost to fidelity**. In one seed `s64l0` validation-force RMSE worsened from 222 to 1,117 meV/Å between epochs 30 and 93. Neither a speed claim nor a change of training objective follows. LoupMD MD kernel times do not identify a training hotspot.

**Gate 0 — no paid engine profile until the stock data path is trustworthy.** Check frozen input digests, teacher/head, atom order, PBC/cells, E/F/stress keys, units, sign, weights and FP64 E0 bookkeeping through materialization and readback. Re-score the final physical model on validation versus the logged metric, and compare error with zero forces by regime/trajectory and with train data. Record which checkpoint/logs were actually retained. Per-epoch validation and final train metrics are not a history of train errors, raw weights or pre-clip gradient norms. If an invariant fails, stop and fix it; if it cannot be checked, report the gap. After input/metric agreement, an isolated `s64r8` throughput profile can inform engineering even if the wide-head fit's cause remains open. Neither fixture measures time to fidelity until it passes §4. Keep the scheduled Stage 0 controls. Do not choose a custom operator from an L4 FP64 trace.

**Current decision: Gate 0 is closed.** On the worst hot-validation frame, digest/head-matched FP64 MH-1 gives a max component discrepancy of **1.3083 eV/Å** against the frozen teacher labels. This is not the whole explanation: on oxygen 138 (zero-based), `Fy` is 3.7778 stored, 3.8472 stock teacher, 163.8798 wide student and 4.0463 narrow student. The wide student's own centered energy difference gives 163.87977 at `h=10⁻⁵ Å`: its large force is present in the learned potential. The earlier ten first-frame spot checks do not clear this geometry. Preserve the original splits, labels and checkpoints; do not remove the frame, start a paid engine profile, or interpret a closed-loop/precision comparison as qualified. Resolve the label discrepancy and its scope first (STATUS §6.70).
The [retained CPU audit](../tools/dev/audit_distill_fit.py) checked all 330 train/validation frames through the actual MACE parser. Materialization is consistent with the files; the files themselves are not all faithful labels. All 24 first-frame controls agreed, but 19/20 second training frames and 17/26 later validation frames failed a 1e−4 eV/Å component check. Four discrepant force labels reproduce when the teacher uses the split's **first cell at current Cartesian positions**. This is a multi-cell, repeated-evaluation regression; one good first call or a fresh single-frame 3× gate cannot clear it. Use fresh and reused native handles, forced list rebuilds and independent FP64, and qualify E, F and stress separately. On fresh teacher labels the hot-frame tail still dominates the wide student; stage two did not initiate the failure. No optimizer mechanism is established.

## Qualification and rollout

1. **Freeze a reference.** Use the pinned Stage 0 recipe, split digests, normalization and checkpoint. Record dependency versions, device, dtype, TF32/autocast and reduction settings. Freeze the actual sequences of minibatch frame IDs for the parity trial; the same integer seed is not enough. Keep validation for selection, and the final teacher-test/independent student-visited sets for acceptance.
2. **Prove the reference before optimizing.** On a tiny skew periodic cell with a nonzero lattice image, compare forces and all stress components with central differences of energy; strain at fixed fractional coordinates and keep the topology fixed. Include a translated/rotated copy, an unequal-size multi-graph batch, repeated species, reordered edges and a frame with zero net force. Use points away from the cutoff for finite differences; separately test behavior on approach from both sides. Include an off-diagonal strain with explicit shear factors.
3. **Prove the parameter update, not only the potential.** Compare unfused vs candidate E/F/stress, energy-only, force-only and stress-only parameter gradients by named block, including zero and near-zero components. Run FP64 `gradcheck`/`gradgradcheck` on each custom op and a random directional finite difference of the **full loss**; sweep the difference step for a stable plateau. Compare the next optimizer update, optimizer moments, EMA and validation output on identical state. Add tests across the phase switch, same-data interruption and augmented restart. Establish absolute floors in physical units and relative tolerances on the reference before looking at candidate results; do not hide a failed species, shear component or small parameter block in an aggregate norm.
4. **Prove a complete run.** Same seed/order, dtype, stress, initialization, eval/save cadence and schedule through both phases. Require the existing §4 fidelity assessment including per-species error, tail, E/S, dynamics and molecular rows when applicable; qualify a second seed and relevant systems before generalization. Use thresholds calibrated only on independent validation data. If neither run reaches the target, report that rather than a speedup to an unachieved target. Keep student-vs-teacher fidelity distinct from the exported engine’s E/F/S 3× rule.
5. **Ship narrowly or stop.** New ops default off until correct and beneficial on the named training GPU(s). Keep an explicit reference backend for unsupported shapes/precisions; log the backend actually used, not the requested one. Never change optimizer, numeric format and implementation simultaneously in a backend comparison. An architecture change is a different experiment.

**Derivation check, CPU only:** a two-parameter radial pair `E = θ₀|d|²/2 + θ₁|d|⁴/4` in a skew cell with a nonzero image and nonzero off-diagonal stress target. The contracted analytic gradient of the squared E/F/stress loss had relative L2 difference `2.23e−9` against centered parameter differences of the loss (step `1e−4`, FP64). This checks the proposed formula on this fixture, not the correctness or speed of a MACE training kernel.
